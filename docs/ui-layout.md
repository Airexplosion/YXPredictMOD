# UI布局错位修复（0.3.3）

0.3.7新增`HorsePlateLayout`：88px图标以ID字形下沿为中心，放在原生昵称之前的同级节点，称号仍作为昵称的子节点。层级模型复现旧子图标会覆盖原生昵称的问题，并验证八个位置在三种缩放、20次刷新及昵称重挂载后均保持图标→ID→称号的顺序；图标不接收点击并跟随昵称显隐，清理时明确销毁独立图标。此模型不替代真实游戏的渲染验证。

## 原因与修复

固定版本SDK的`UiKit.Label`创建两层对象：外层同名RectTransform保存传入的位置和尺寸，内层`text`节点才是返回的TextMeshProUGUI。内层拉伸填充外框，边距为左右6、上下2。此前总表切换模式时直接修改返回文本的anchoredPosition和sizeDelta，等于在伸展节点上再次叠加绝对坐标。

以截图的简洁模式为例，174宽的名字框在x=18，给内层再次设x=18、width=174后，其左边界变成-51；结果框原在x=840，给内层设x=716、width=386后，其左边界变成1363，超过1120宽的面板。预览和历史表头也存在同样问题。SDK本身没有把这些坐标当作外框坐标。

新增`Game/UiTextBox.cs`，明确通过返回文本的父RectTransform移动/缩放外框，保留内层stretch及边距。名字、预览、结果及历史表头都使用这一入口。按钮和输入框继续移动各自根节点，不改变玩家UID绑定或交易回调。简洁及详细模式均把名字与命元/称号分成两行，长文本单行省略，防止覆盖下一行；窄列标题调整字号。面板使用不透明底色和RectMask2D限制内容区域，标题显示当前版本号。

顶部马图挂签同样由两层SDK文字组成。测量到的TMP字形上沿先通过TransformPoint和InverseTransformPoint转换到挂签根节点，再用于ID下方1单位间隔计算，消除内层位置造成的额外间隙。曲线标题置顶也改为操作完整外框。

## 回归检查

`tools/UiLayoutChecks`直接编译生产代码`UiTextBox.cs`，使用独立二维RectTransform锚点模型验证坐标；同时用Mono.Cecil检查当前SDK确实提供上述两层结构。检查内容包括旧问题的-51/1363偏移复现、八行控件反复切换简洁/详细/历史、1及0.65缩放、历史表头、嵌套字形的1单位间距及整框置顶。

完整`./scripts/build.ps1`在游戏构建和静态校验之后、打包之前执行这些检查。模型不模拟真实字体栅格化、Unity原生渲染或客户端Canvas状态，不能代替实机显示检查。核心108项回归与官方ILRuntime探针继续保留。只新增布局检查工具，没有改动SDK或积分存档格式。
