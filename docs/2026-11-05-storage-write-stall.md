# 整点实场磁盘阻塞修复

北京时间 2026-11-05 的 15 点场复现：WHITE 在线、原生观战继续更新，但开场通知未送达，抓取端后台请求反复超时。前次仅改连接恢复与重复帧合并，未解决实场阻塞。

现场证据：后台 Node 主线程处于 D 状态、等待 `rq_qos_wait` / `wait_on_page_bit_common`，本机健康检查连续超时；进程约三个多小时累计写盘 40 GB，磁盘等待占比约 99%。每次事务同步重写约 36.8 MB 完整 JSON，是本次写入压力的直接来源。磁盘未满，QQ 未掉线，也未发现这场由新版公开协议解析或缺少图片造成阻塞。

`state-store.mjs` 将完整逻辑账本编码为 Brotli quality 1 + Base64 的版本化 JSON 容器；真实账本只读往返严格相等，文件从 36,757,322 字节降至 4,765,604 字节。余额、持仓、已锁定奖励、幂等回执、结算、通知租约与历史均完整保留。仍在临时文件写入并 fsync 后原子重命名，保存失败继续触发原有内存回滚，不提前确认成功。容器校验原始字节数及 SHA256，限制解压预算。

兼容与运维：

- 启动兼容旧明文账本，下次成功保存才迁移，文件位置仍是 `ROOM_DATA/rooms.json`。
- 文件根层现在是 `yx-prediction-state-br-v1` 存储容器。诊断工具必须通过 `state-store.mjs` 的 `readState(file)` 读取逻辑账本，不可直接将 `JSON.parse(file)` 当作账号/房间对象。
- 回退旧服务前先停止写入方，用新解码器导出**最新**逻辑账本，fsync 并原子替换成旧明文格式，然后启动旧服务。不得用旧备份覆盖期间产生的交易。部署脚本包含此回退流程。
- 原始账本备份、生产数据和运行素材仅存服务器受限目录，不提交仓库。
