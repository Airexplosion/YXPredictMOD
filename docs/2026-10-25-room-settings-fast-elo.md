# 0.7.6 房间设置、普通参赛称号与Elo加速

用户要求创建先设置、确认后直接观战，检查正常天梯/道心称号，加速Elo，并拉取上游新功能。本轮合并上游9fdff4e（0.7.5）；上游已经合并原PR #1，新增0.7.4最终结果队列持久保存/补发和两界面UID名次草稿同步、已购玩家置顶；0.7.5总览固定居中/禁止拖动并仅保留底部入口。合并保留这些行为。本地fork原有正式Release指针保持不变，避免合并源码触发正式发版。

创建先显示独立设置页，“匹配：开启/关闭”和“创建并观战”；目标在设置期间切换则禁用并拒绝旧目标。有房间时继续隐藏创建。确认走当前原生观战按钮，同步查找刚打开的原生“是否观战”窗口并调用其确认Button.onClick；既有窗口、多个窗口、文案/控件不匹配、按钮禁用时不代点，原生权限/组队准备/离队检查仍运行。未直接调用网络观战或切场景。当前热更重新用yx-patch refs提取，核对XianFuLobbyRoomDetailItem.OnSpectateButtonClick、XianFuLobbyPanel.SpectateRequest、LobbyManager.SpectateRequest及MessageBoxWindow字段。厂商DLL/反编译仅在忽略refs内。

allowMatch随创建请求跨观战等待传递，服务器校验布尔并持久保存，关闭时只排除随机匹配，本局发现/房间号邀请仍可加入。旧记录缺字段默认开启，重复create不能覆盖已有房主设置。回包和房间底栏包含匹配状态。

Elo最多4个UnityWebRequest并行，同后缀请求合并；结束即补新片，Revision触发主桥即时刷新。缓存256个目标资料，失败30秒后可重试，和未收录分开统计。只在有任务时启动每帧计时器，每帧最多解码一个新响应，所有扫描共用约2ms软预算/64步上限，每步1024字符，轮转执行。IndexOfAny在BCL跳过普通值字符，普通键直接切片，保留转义/括号/边界及目标尺寸检查。全在Unity主线程，无后台解释器。

离线ILRuntime2.1对照：同一141895字节（139816字符）公共分片、目标在末尾、每步1024、预热后3次中位数，总扫描CPU旧288.42ms、新79.63ms，约3.6倍。不是单帧阻塞或网络总耗时，实际客户端帧时长待实机测量。原有分帧不阻塞策略保留。

普通天梯/道心使用GameBridge采集完整名单，TianJiFeature调用同一个EloClient，未用LiveObserver限制称号；门槛只限制预测。新增普通参赛快照回归证明特等/上等/中等马分档及道心资料保留，同时不开盘口不扣积分。未收录不编造分档，战斗播放隐藏头像覆盖，回备战恢复。称号生产源码本轮与上游完全一致，不宣称已在用户实际天梯/道心局中验收。

验证：131 C#、34 Node、17原生入口/确认、53头像模型、60仙命布局、7组生产RoomClient、29项生产EloClient网络替身通过；官方ILRuntime、MOD Release与yx-patch --warn-as-error均通过（MOD 0 warning/0 error）。新包另核验CRC、manifest/README/DLL逐字节、内容白名单/厂商引用排除/源码控制字节。没有运行指向旧正式Release的源码一致性校验。
