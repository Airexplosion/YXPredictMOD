# WHITE 查询与增量账本

原整份账本压缩后仍约 4.8 MB，每次事务仍复制全部历史并同步写盘，余额查询还会执行钱包同步。现场本机健康检查连续 4 秒超时，QQ 状态接口为 1～3 毫秒。

新增 `IncrementalStore` 使用 Node 内置 SQLite，按账号、房间、回执和单条通知保存。每次事务只更新序列化内容改变的记录，并以 WAL + synchronous=FULL 提交。多账号余额、持仓、幂等回执仍属于同一数据库事务，提交失败保留旧缓存并触发业务回滚；无变化不提交事务。通知顺序、空容器与已送达租约完整保留。

QQ 钱包同步只备份 accounts / profiles / qqBindings / identityAliases / walletEvents；房间持仓保持只读。作用域内数据未变化时直接返回，不再序列化历史账本。新绑定、合并钱包、首次开户、救济金与实际交易仍走保存确认，嵌套事务服从外层原子提交。

存储与回退：

- 主账本现在是 `ROOM_DATA/rooms.json.sqlite`，旁边可能有 `-wal` 与 `-shm`。迁移成功后旧 `rooms.json` 仅为迁移来源，不再随交易更新。
- `readState('.../rooms.json')` 自动优先从 SQLite 的一致性快照读取，兼容现有诊断入口；旧 `writeState` 遇到增量数据库会拒绝覆盖。
- 备份应从 `readState` 导出完整逻辑账本至受限备份文件，或在所有写入方关闭后备份数据库。不能只复制运行中的主 SQLite 文件而遗漏 WAL。
- 回退必须先停写，导出**最新** SQLite 逻辑账本，原子保存为旧版压缩格式，将 SQLite/WAL/SHM 一起移至受限回退目录，再启动旧服务。不能直接恢复旧 JSON 或旧备份，否则会丢失迁移后的交易。
- 单写进程锁保持，数据库文件权限为 0600。部署脚本包含失败回退，未改余额或补算历史。

验证：本地与 PR 工作区 250 项测试覆盖旧明文/压缩账本迁移、原 HTTP 重启、跨账户原子保存、SQL 写入失败回滚、缓存重试、通知增删排序、WAL 异常退出恢复、钱包作用域回滚和无变化不保存。服务器初版 249 项通过，真实账本隔离副本的单账号变更仅更新 1 条、32 字节；该机器压力下序列化比较约 0.8 秒，因此又增加无变化钱包查询直接返回。

部署状态：增量存储已在服务器迁移并逐项校验一致，服务切换后健康检查曾成功；随后该主机 SSH 与两站 HTTPS 从多个来源同时无法连接。无变化查询的最后优化尚待主机恢复后发布，暂未完成最终延迟验收。WHITE 的连接失败中文提示已独立上线，机器人 QQ 登录保持。不要把目前的主机失联误写成优化已完成实场验收。
