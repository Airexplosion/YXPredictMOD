# 田忌赛马整合记录（0.3.0）

来源为用户提供的 HZ「田忌赛马」`com.hz.tianji-1.9.3-src.zip`，SHA-256：`c95aa2d48617832c975afc1fe306ec8d05aef3e2fb759014fa0f5b7e6f485c4d`。保留六张原始马图；称号数据、状态与界面绑定按现有项目结构重新实现，不装载原DLL、不执行原构建脚本。

## 审查发现及处理

| 原源码问题 | 整合后的处理 |
|---|---|
| 以昵称查names.json，并把游戏UID改成站点UID；同名、改名时可能查错，名单指纹也可能反复变化。 | 按游戏UID直接读已有Elo分片，身份不改写；与预测共用查询和缓存。 |
| 指纹只含UID且一致时提前返回，后到的名字、天梯分不能合并，同名单新一局不重置。 | 按真实对局ID重置，逐次按UID合并资料，可选天梯消息须匹配完整八人名单。 |
| 每两秒胜场差须达到2才判黑马，正常每轮加1胜难以触发，首次累计胜场却可能误触发。 | 建立观察基线，连续两轮胜场各加1且无新增负场才判定；重复消息不计数，缺轮不推断。 |
| 黑马重评覆盖整个tag，旋转木马被清空。 | 赛季标签与局内黑马独立保存，黑马消失后恢复基础称号。 |
| 扫描TMP文本匹配昵称可能误绑同名或其他面板，挂签不随称号刷新。 | 读取真实头像布局，以battlePlayerData.uid绑定，每次刷新。 |
| 切局、停用只清字典，挂签残留，显隐未完整限制场景。 | 切局、离开对局、关闭称号、动画期间及停用清理挂签；停用销毁Sprite/Texture。 |
| HorseAssets未实际使用，配置绑定顺序错误，目录依赖工作目录。 | 六图按需解码缓存，构建时确定性生成DLL图片载荷，运行时不猜安装路径、不逐像素处理。 |
| 自制JSON解析缺少坏数据保护，多处异常被吞掉。 | 复用SDK JSON、请求超时和响应上限；可选赛季字段检查缺失、NaN及范围，显示错误记日志。 |

## 规则与显示

八人真实Elo最高为特等、第二上等，其余中等，最低牛马；最低较上一档低至少400分为海马。同分同档，全员同分或仅一人有真实Elo用中等；未知3000基准不参与评选。已查到Elo的后半玩家，逐轮观察到连续两胜且存活时为黑马，可多人获得。新增负场、缺轮或淘汰停止对应连胜判定；迟到观战及重载不推断过去连胜。

最近数字赛季需有完整start/end/peak，peak比start至少高150、end不高于start才附加旋转木马。数据站dx为道心对局数，显示“道心对局N场”；实际天梯/道心分仅在收到本局匹配的消息时显示，观战未收到时省略。这些称号仅作趣味参考。

用户选择保留原头像，在昵称下方加马图小图标、称号及Elo±sigma。挂签不接收射线，随头像排序、移动和昵称显隐变化。单人面板显示称号说明，简洁总表附短称号，详细模式附完整标签，历史不套用当前局称号。面板“称号：开/关”与管理器tianji.enabled共用；tianji.icons单独控制图片。没有快捷键。

对战与观战均可显示称号，积分下注仍只允许原有的实时观众。此模块不写积分、赔率、最终名次或存档。源码仅在读取私有BattlePanel和可选天梯消息时进行限定字段反射，避免原MOD记录的跨程序集字段token错配，不进行全场昵称扫描。

## 验证

新增回归覆盖同名UID、最新赛季、异常数值、同分、缺失Elo、逐轮连胜、重复消息、同轮多次变化、中途加入、缺轮、重排、改名、同名单切局、旧状态回退及淘汰。ILRuntime探针执行称号、赛季解析与切局重置。编译和静态检查覆盖游戏绑定及图片调用；挂签位置、图片展示及连续整局仍需实机确认。
