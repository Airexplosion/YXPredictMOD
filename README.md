# 弈仙牌观战名次预测 MOD

已实现积分版完整流程：实时八人观战 → UID 查询 Elo → 按公开局势动态报价 → 每轮买入/增持/减半/清仓/换预测 → 逐人结算 → 持久化余额和持仓。

认证时长接口按当前需求留空，不读取、扣减或增加加载器认证时长。首次积分 1000，操作说明见 [mod/README.md](mod/README.md)。

## 安装

将 `dist/local.yxp.predictionpoints-0.2.9.zip` 导入弈仙牌 MOD 管理器并启用。点击右上角、回合标识左侧的「名次预测」打开当前观战玩家的单人面板。顶部玩家ID与Elo分数同一行放大加粗，不再重复显示命元。命元图与占比图左右各占一半，换牌走势图暂时隐藏并收紧面板高度。点击「展开全部」打开八人总表，「收起」回到单人面板；切换观战对象后自动跟随。「上一局 / 下一局」仅在查看历史记录时显示。入口可拖动，动画时隐藏，已保存的位置继续有效。也可把 `mod/` 加为开发目录；没有快捷键。

0.2.9 修复淘汰后奖励一直待结算：游戏协议的名次为0～7，读取时统一转换为模组内部的1～8，同时修正最终结果中的第1名。锁定返还权益及存档格式不变，已有待结算持仓在重新收到同局正确状态/最终结果后补结算；没有收到的结果不能仅靠命元历史恢复。新增反馈场景、旧存档恢复、重复领奖防护等回归检查。

安装包已声明更新地址 `https://github.com/Teraen/YXPredictMOD`。管理器通过公开GitHub Releases比较版本；后续发布需递增manifest版本并创建同版本的正式Release、附上安装ZIP。旧包未声明更新地址，本次需要手动导入覆盖。

0.2.8 的目标名次在单人面板与总表间同步，买入及换预测后跟随实际持仓。未购买且未手动选择的玩家显示「？」；首次点击「+」选第1名，首次点击「−」选第8名，随后在1～8名循环；也可点击名次框直接输入。未选择时不能买入。总表将已购入项置顶，各组保留原玩家顺序；清仓后回到未持仓组。

命元走势按UID记录所有玩家已收到的回合数据，每回合保留最新值，缺失轮次不连线，最多保存最近128个回合采样。升级前或加入观战前没有收到的历史不会补造，重载后保留已记录的走势。

0.2.3 新增命元占比图，按同回合的当前玩家命元除以八人命元总和计算，显示到两位小数的百分比。负命元按0计，总和为0或数据不完整时留空；可利用已有完整回合记录。赔率显示为两位小数，锁定报价与结算精度不变。

0.2.4 的三类图表分别使用八人共同的动态纵轴及回合范围，按所有已记录数据的整体范围留边距，不再强制从0起画；包含变化最大玩家的数据且不会裁掉其他人的值。换牌次数为最近同步值，优先使用UID匹配的私有状态，否则使用公开字段；同轮保留最新值，不回填未知历史。

0.2.0 的新盘口取消第 5 轮永久封盘：每轮修炼阶段都能调仓，收到本轮结果就暂停，下一轮重新开放。前 5 轮仍有早猜利润加成。报价结合冻结的 Elo、命元、胜负轮数与淘汰名次；每次买入锁定新增返还权益，出售按当前价值折价 3%。差一名返还剩余正中权益的 25%，向下取整。旧盘口保留原有固定投注及结算规则。

当前交付为可编译、可安装的开发版。**尚未实机验证 UI、Unity 网络访问和连续完整对局**；安装后请先用积分测试。

## 构建与验证

Windows PowerShell，项目根目录：

```powershell
# 第一次获取固定版本 SDK（后续会逐文件复核 Git blob 哈希）
./scripts/restore-sdk.ps1

# 第一次或游戏更新后，从自己安装的游戏生成引用
./scripts/prepare-game.ps1 -GamePath 'C:\Program Files (x86)\Steam\steamapps\common\YiXianPai'

# 流程测试 + ILRuntime解释器执行 + 完整游戏构建 + 静态校验 + 打包
./scripts/build.ps1

# 同时输出模拟八人局流程；演示数据不写真实积分存档
./scripts/build.ps1 -Demo

# 没有游戏时，只测核心逻辑并构建 Core DLL（无游戏面板、不打包）
./scripts/build.ps1 -CoreOnly
```

本项目的检查程序适配 .NET 6+ SDK；SDK 提供的 `yx-patch` 工具需要 .NET 8 运行时（或按其配置滚动到更高版本）。推荐安装 .NET 8 SDK；本机以 .NET SDK 6.0.428 + .NET 8.0.15 运行时验证。

`restore-sdk.ps1` 从官方仓库恢复 SDK、示例、文档及工具，固定版本 `744137755d7daa60a8e9e4492bb7bcecad92fa76`，逐文件验证上游 Git blob SHA-1。`prepare-game.ps1` 从官方发行版下载 Il2CppDumper v6.7.46，并校验 SHA-256；只读游戏、在项目 `.cache/` 和 `refs/` 下写文件。不修改游戏、管理器配置或认证数据。

`vendor/`、`refs/`、`.cache/` 不提交；`refs/` 为游戏厂商的内容，不分发。安装包只包含本模组的 DLL、manifest 和使用说明。

## 结构

- `mod/src/Core/`：赔率、盘口、扣款、结算、JSON 存档；不依赖 Unity。
- `mod/src/Game/`：实际游戏状态绑定、非阻塞 Elo 请求、可拖拽按钮入口及预测界面。
- `tests/`：97项核心/SDK宿主检查，以及编译为net40后在ILRuntime解释器中执行的新旧流程、三类走势持久化、统一坐标轴、名次选择同步及协议名次转换补结算探针。
- `scripts/`：依赖恢复、游戏引用生成、构建打包。
- `docs/design.md`：规则、边界及认证时长后续对接要求。
- `tools/InspectAssembly/`：只读程序集类型/字段/IL 查询工具，便于游戏升级后核对绑定。
- `tools/InterpreterChecks/`：运行官方ILRuntime v2.1.0，验证旧盘口和动态调仓中的开盘、增减仓、换预测、结果封盘、存档恢复与结算；首次构建下载源码到 `.cache/ILRuntime/` 并校验归档哈希，测试代码不放进安装包。

0.1.2修复了0.1.1查分完成后无法开盘的问题：二维数组访问在ILRuntime解释器中出现越界，另有下注运算使用了不受支持的溢出检查指令。现改用一维数组和明确的数值边界检查，并把解释器执行加入默认构建检查。赔率和积分存档格式保持兼容。
