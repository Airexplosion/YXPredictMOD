# 名次预测 0.7.0 测试版

单人和多人共用旧版预测窗体与角色下注条。新联机房间使用“单人基础倍率 × 投注修正系数”；其余交易与返还规则对齐原单人账本。积分不可购买或兑换认证时长。

## 倍率与玩法

- 基础倍率继续来自现有单人Elo/公开局势/当前回合算法，不取资金池比例作为倍率。
- 没有人投注时系数为1。上轮剩余持仓投入占比调整本轮系数，范围0.75–1.25。公式为 clamp(1 + 0.25 × (1 − 8 × 此名次投入占比), 0.75, 1.25)。每轮开始锁定该轮系数；本轮投入不改变当前系数。
- 原单人公开局势导致的基础报价刷新仍可发生；投注系数只在新回合更新。最终报价限制和原单人一致，不可能名次为0、可买报价在1.01–50倍之间。
- 买入按当时报价锁定权益；后续报价不改旧权益。正中返全部权益，差一名返权益25%，其他不返。首尾名次不环绕。
- 增持增加当次权益；退半卖出权益的一半并向下取整，清仓卖全部权益，返还按当前报价折算后扣3%，和单人一样。换猜原子出售旧仓再买新仓，失败整笔恢复。
- 淘汰名次确认后按原单人规则提前结算，最终结果不重复派奖；每人对每名选手最多512次操作，单次1–10000整数，余额上限与单人相同。

旧资金池房间保留原结算承诺，不追改既有持仓；界面明确显示旧房间。房主及参与者均更新0.7.0后，在新的对局创建新房间使用新规则。单人余额和联机余额仍分别保存，算法一致不代表转移或合并余额。房主提供原单人计算出的基础报价与原生结果，服务端统一系数、版本、权益和派奖；本版没有独立官方身份/战果验证。

## 使用

仙府大厅选择对局，点原生“观战”旁的“名次预测”。查询当前对局是否已有房间，没有则创建、有则直接加入；匹配可选择其他开放且已有投入的房间，操作走游戏原生观战确认与权限流程。进入当前实时观战后，单人直接使用同一界面，加入房间则使用联机余额。

右上角“预测总览”和底部“总览”打开同一个窗口，再点关闭；按要求移除面板“透视”按钮，SDK低层能力保留供其他MOD使用。

总览顶部“走势图”恢复命元、命元占比、剩余换牌次数，上一人/下一人切换，坐标按八人共同范围生成。图表只展示自己实际收到的回合，迟到/漏轮不造数据。走势图在单人和多人均可用，历史多局列表不恢复。

选择名次后，倍率列显示当前报价；多人右侧同时显示“基础倍率 × 投注系数”。没人投注也有基础报价。输入读取当前数字，不会刷新回10。入房原生提示显示游戏名和ID，重复刷新不重弹。

## Elo卡顿修复

HTTP请求原本就是异步，原来的卡顿风险来自返回后在ILRuntime主线程整份Json.ParseObject。现在按256字符小段扫描并在约1ms软预算后让出，只反序列化当前/缓存目标UID的资料，不创建同分片所有玩家和历史的对象；转换后的HorseProfile缓存复用。缓存有上限，新名单补查，未知/失败明确标注，不把热更解释器放到后台线程。

真实样本00分片约142KB、283名玩家，完整解析不再在查询完成的一帧执行。1ms是软预算，不是实机最大帧耗时保证；单条选中资料反序列化、Unity读取响应文本、首次马图解码和其他UI工作仍可能耗时。此版尚无实机帧耗时测量，不能宣称所有卡顿已经消失。
